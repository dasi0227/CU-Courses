Formula 复现与对照实验

实验定义

A：空手册 baseline。使用 ACE 预处理后的题目和 Generator 提示词，保持手册为空，直接回答测试题，不进行训练。
B：3 轮 ACE。答错后最多进行 3 轮“反思、重新回答”，改对则提前停止；训练时逐题整理经验，用验证集选择最佳手册，最终固定手册测试。
C：Jev 读取选择。复用同一 trial 的 B 最佳手册，使用现有固定 decision 指令根据当前测试题对条目相关性评分，固定读取前 5 条经验；手册不超过 5 条时读取全部，无需 Jev 评分。C 不重新训练、不改写手册，也不额外运行验证集选择 k，直接评测测试集。Jev 不生成答案，也不判断数值是否正确。

对照关系：A/B 检验经验手册收益，B/C 检验 top-5 读取选择。三组测试时每题只生成一次。

数据与配置

small：按 50 种公式分层抽取训练集每类 2 题、验证集每类 1 题，测试集保持完整；共 100/50/200 题，1 epoch，每 20 步验证，3 次重复。这是本次使用的缩减规模配置，不能宣称严格复现论文数值。
paper：使用仓库的 500/300/200 题，5 epochs，每 100 步验证，3 次重复；仅保留为可选配置，本次不额外执行。名称表示数据规模与训练遍数对齐，B 的反思上限已按本次方案改为 3 轮，不再保留上游默认的 5 轮。当前采用 Terminus 更新版及百炼服务，不能视为与论文原版 V3.1 严格同模型、同服务的复现。
smoke：训练/验证/测试各 2 题，1 epoch，每 2 步验证，1 次；与正式配置一致，C 固定 k=5。它只供离线流程检查，不能作为正式指标。

原始 JSONL 保持不变，新目录的 plan.json.data（历史结果目录为 plan.v8.json.data）记录源文件 SHA-256、抽样种子、源行号和稳定样本 ID；三组统一使用现有的 ACE 题目预处理和 Generator 提示词。
每个正式 trial 只独立训练 B；C 只复用同 trial 的 B，不能跨 trial 或跨配置复用。三次重复使用相同数据划分和顺序，报告实际运行间变动。
C 固定 k=5，不再额外回答验证集。small 每 trial 的 C 只对 200 道测试题各调用一次 Generator，共 200 次（不含异常重试），另有 Jev 相关性评分请求。B 的手册训练与验证是两组共享的前置投入。

模型与环境

三组统一通过阿里云百炼北京地域调用硅基流动提供的 siliconflow/deepseek-v3.1-terminus，api_provider=dashscope，region=cn-beijing，base_url=https://dashscope.aliyuncs.com/compatible-mode/v1。三个 ACE 角色共用同一模型和 Key，temperature=0，enable_thinking=false；OpenAI 兼容接口通过 extra_body 关闭思考。输出上限 4096 tokens，batch_size=1。
Terminus 是 DeepSeek-V3.1 的更新版，服务商也从上游默认的 SambaNova 改为百炼入口下的硅基流动。报告需记录模型版本与服务商差异；在控制台开通模型并授权之前，配置存在并不代表账户已具有调用权限。
Jev 固定模型 jev-1.13.0，端点 https://api.typesafe.ai/v1/systemone，相关性评分每批最多 20 条。所有配置固定 k=5，不接受 k_candidates 或验证集调参；每道题选中的经验可以不同。
项目根目录 .env 使用 DEEPSEEK_API_KEY 和 TYPESAFE_API_KEY。前者只是本地变量名，值必须是百炼北京 Key，请求走百炼而非 DeepSeek 官方。A/B 只需百炼 Key，C 还需要 Typesafe Key。不要把密钥写入配置、日志或提交文件；此次改动不修改实际 .env。
官方接口说明：https://help.aliyun.com/zh/model-studio/siliconflow-deepseek-api

运行入口

在项目根目录使用：
.venv/bin/python -m eval.finance.experiments

默认等同 --dry-run，只将计划与样本清单写入计划文件，不调用 API；新目录使用 plan.json，已核验的 v7 历史结果目录使用 plan.v8.json。
--mock 默认使用 smoke 配置与离线替身，默认输出为并列的 results-mock/，不生成真实成绩；显式 --output 优先。
只有显式 --execute 才会请求真实模型；它与 --mock、--dry-run 互斥。
--config 指定 JSON；--groups 后用空格分隔 A B C；--trial 为 1 到 repeats，不指定则运行全部重复；--output 指定共享输出根目录，B、C 必须使用同一目录。
正式实验默认输出根目录为 /Users/wyw/Desktop/Courses/FTEC5660/Reproducibility/ace/results/，不再增加 small-run 时间戳、formula 或 trial_01 层。先按组、再按重复编号保存：A/01/、A/02/、A/03/，B/C 同理。另做独立实验或更换配置时，用 --output 指定另一个输出根目录，避免覆盖或混入现有结果。

查看参数：
.venv/bin/python -m eval.finance.experiments --help

检查 small 计划：
.venv/bin/python -m eval.finance.experiments --config configs/formula/small.json

离线检查：
.venv/bin/python -m eval.finance.experiments --mock

以下命令仅作真实执行示例，此次没有执行：
.venv/bin/python -m eval.finance.experiments --execute --config configs/formula/small.json --groups A B
.venv/bin/python -m eval.finance.experiments --execute --config configs/formula/small.json --groups C

以上命令省略 --trial 时各运行 3 次；如需分次运行，分别加 --trial 1、2 或 3。C/01 只读取 B/01 的手册，其余重复同理，B、C 必须使用同一输出根目录；已有组和重复结果不会被覆盖。paper 配置需更换 config 路径并另用 --output 指定一个输出根目录。
正式执行前核对计划中的数据规模、组名、trial、模型、端点、Key 变量名和输出位置。使用新结果目录，避免混用先前实验编号、服务商或模型配置对应的结果。


结果文件（下列路径均相对于输出根目录）

新输出目录保存以下 3 个公共文件；受保护的 v7 历史目录使用下述兼容文件名：
plan.json：整体实验配置、代码校验值与 plan.json.data 中的完整数据来源和抽样清单。
invocations.jsonl：每次启动的组别、重复编号、模式和时间。
summary.csv：各组准确率均值、样本方差、调用用量与耗时汇总；各次完整结果仍在对应 result.json。

各组的 01/02/03 目录均保存以下 3 个文件：
llm_calls.jsonl：按行追加所有阶段的 DeepSeek 请求，完整保留角色、提示词、回答、Token、耗时和错误；使用 stage 与 call_id 定位单次调用。另以 processing_error 事件记录解析和 Curator 应用错误，这类事件不计作额外 API 请求。
predictions.jsonl：逐题保存最终测试的样本 ID、预测、标准答案、正误与错误信息，直接放在各组重复目录下；不再复制原始回答、final_answer 或重复成功标记，原始回答通过 stage/call_id 关联 llm_calls.jsonl。
result.json：本组本次的运行状态、test 中的测试指标、predictions_path 绝对路径、各阶段调用与 Token 汇总、耗时及 errors 中的 API、解析和 Curator 应用错误；不再嵌入完整逐题预测。B 的 training_config 保留训练入口实际参数和 effective_parameters，training 保留训练摘要。C 还保存 selection_k=5、selection_method=fixed_top_k、b_checkpoint 中的 B 手册路径与 SHA-256，以及共享 B 训练和验证用量；这些来源信息在测试开始前落盘。

B 再保存以下 2 个训练文件：
training/train_results.json：合并逐题更新手册前后的答案和正误、实际反思轮数，各次验证的逐题预测、指标与手册大小，以及 best_checkpoint；small 正常完成时有 5 次验证。每个训练步骤后更新，失败时保留已完成记录和状态。
training/best_playbook.txt：验证准确率提升时立即保存的最佳手册；C 直接读取同编号 B 的文件，并核对 SHA-256。

C 额外保存 jev_audit.jsonl，记录 Jev 的评分输入、候选经验、相关性分数、选中条目、Token、耗时和错误，便于追溯 top-5 选择。
三次重复的三组全部正常完成后，共有 39 个常规输出文件：3 个公共文件、27 个各组共有文件、6 个 B 训练文件和 3 个 C 审计文件；历史兼容记录另计。

不再生成独立 data_manifest.json、summary.json、test_metrics.json、evaluation_playbook.txt 或 frozen_selection.json，也不再生成独立请求 JSON、detailed_llm_logs、run_config.json、final_results.json、val_results.json、pre_train_post_train_results.json、bullet_usage_log.jsonl、curator_operations_diff.jsonl、final_playbook.txt 和 intermediate_playbooks 快照；需保留的配置、逐题训练与验证信息、错误和最佳手册已先并入上述文件。原始调用仍完整保存，必要时可据此复查经验引用和 Curator 操作。
日志逐条追加、训练记录逐步保存；完整测试预测在该次评测完成后保存。这种持久化不等于自动断点续跑，现有已运行组和重复仍不会被覆盖。

评测与结果解释

B 固定验证集选出的手册，C 复用 B 的同一份最佳手册并预先固定 k=5；测试标签仅用于程序评分，不传给模型或 Jev。
三组统一使用数值 Exact Match，不额外放宽数值容差。分母固定为全部测试题，API 或解析失败保留记录并计错，不跳过样本提高准确率。
正式配置汇总 3 次准确率的均值、样本方差，记录 API 完成率、各阶段调用数、输入/输出 Token、耗时、实际反思轮数和手册大小。
百炼与 Jev 用量分开记录；Token、API 调用次数和延迟不是费用，需要明确计费规则或账单证据才能换算。
C 同时报告自身增量用量和加上共享 B 学习过程的总用量；共享部分包含 B 训练和验证，不含 B 的测试调用。整体费用只将同一份 B 学习投入计一次，避免因复用或重复归因失真。
mock 输出、Token 和耗时只用于离线诊断，不混入真实实验汇总。
