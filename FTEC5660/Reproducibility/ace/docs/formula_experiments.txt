Formula 复现与对照实验

实验定义

A：空手册 baseline。使用 ACE 预处理后的题目和 Generator 提示词，保持手册为空，直接回答测试题，不进行训练。
B：3 轮 ACE。答错后最多进行 3 轮“反思、重新回答”，改对则提前停止；训练时逐题整理经验，用验证集选择最佳手册，最终固定手册测试。
C：Jev Score 读取选择。复用同一 trial 的 B 最佳手册，使用固定 decision 指令根据当前测试题对每条经验给出 0–3 Score 评分，按 score 降序读取前 10 条；同分保持手册原顺序，confidence 仅记录审计、不参与排序。手册不超过 10 条时读取全部，无需 Jev 评分。C 不重新训练、不改写手册，也不额外运行验证集选择 k，直接评测测试集。Jev 不生成答案，也不判断数值是否正确。评分等级固定为：0=无关；1=仅话题相关或泛泛提醒；2=辅助步骤可用；3=直接支持核心公式或关键计算步骤。

对照关系：A/B 检验经验手册收益，B/C 检验 top-10 读取选择。三组测试时每题只生成一次。

数据与配置

small：按 50 种公式分层抽取训练集每类 2 题、验证集每类 1 题，测试集保持完整；共 100/50/200 题，1 epoch，每 20 步验证，3 次重复。这是本次使用的缩减规模配置，不能宣称严格复现论文数值。
当前仅提供 config.json。training.max_num_rounds 设置 B 的反思上限，当前为 3；运行组由 --groups 选择，A/C 不训练。模型采用 Terminus 更新版及百炼服务，不能视为与论文原版 V3.1 严格同模型、同服务的复现。

原始 JSONL 保持不变，plan.json 仅保存配置快照和训练、验证、测试样本 ID。数据路径、抽样种子及规则保留在配置快照中，ID 包含数据划分和源行号，不另存重复字段；三组统一使用现有的 ACE 题目预处理和 Generator 提示词。
每个正式 trial 只独立训练 B；C 只复用同 trial 的 B，不能跨 trial 或跨配置复用。三次重复使用相同数据划分和顺序，报告实际运行间变动。
C 固定 k=10，不再额外回答验证集。small 每 trial 的 C 只对 200 道测试题各调用一次 Generator，共 200 次（不含异常重试），另有 Jev 相关性评分请求。B 的手册训练与验证是两组共享的前置投入。

模型与环境

三组统一通过阿里云百炼北京地域调用硅基流动提供的 siliconflow/deepseek-v3.1-terminus，api_provider=dashscope，region=cn-beijing，base_url=https://dashscope.aliyuncs.com/compatible-mode/v1。三个 ACE 角色共用同一模型和 Key，temperature=0，enable_thinking=false；OpenAI 兼容接口通过 extra_body 关闭思考。输出上限 4096 tokens，batch_size=1。
Terminus 是 DeepSeek-V3.1 的更新版，服务商也从上游默认的 SambaNova 改为百炼入口下的硅基流动。报告需记录模型版本与服务商差异；在控制台开通模型并授权之前，配置存在并不代表账户已具有调用权限。
Jev 固定模型 jev-1.13.0，端点 https://api.typesafe.ai/v1/systemone，使用 Score 原语，评分每批最多 20 条。四档是评分锚点；官方 Score 返回概率加权均值，可为小数。返回值须为 0–3 有限数值 score 和 0–1 有限数值 confidence，按原始 score 排序，不取整；保留条目完整性、类型和范围校验，缺失、越界或类型错误均使运行失败，不补默认分、不裁剪分数、不回退为 Noul。probabilities 原样保存到审计，不要求总和等于 1，不据此重新计算 score；confidence 仅审计，不参与排序。所有配置固定 k=10，不接受 k_candidates 或验证集调参；每道题选中的经验可以不同。
项目根目录 .env 使用 DEEPSEEK_API_KEY 和 TYPESAFE_API_KEY。前者只是本地变量名，值必须是百炼北京 Key，请求走百炼而非 DeepSeek 官方。A/B 只需百炼 Key，C 还需要 Typesafe Key。不要把密钥写入配置、日志或提交文件；此次改动不修改实际 .env。
官方接口说明：https://help.aliyun.com/zh/model-studio/siliconflow-deepseek-api
Score 原语说明：https://docs.typesafe.ai/primitives/score；criteria 是按 0 开始的有序字符串数组，顺序对应上述四档。

运行入口

在项目根目录使用：
.venv/bin/python -m eval.experiments

默认等同 --dry-run，只将配置快照与样本 ID 写入 plan.json，不调用 API；已有计划先严格校验，不覆盖。
只有显式 --execute 才会请求真实模型；它与 --dry-run 互斥。
--config 指定 JSON；--groups 后用空格分隔 A B C，未指定时运行三组；--trial 为 1 到 repeats，不指定则运行全部重复；--output 指定共享输出根目录，B、C 必须使用同一目录。
正式实验默认输出根目录为 /Users/wyw/Desktop/Courses/FTEC5660/Reproducibility/ace/results/，不再增加 small-run 时间戳、formula 或 trial_01 层。先按组、再按重复编号保存：A/01/、A/02/、A/03/，B/C 同理。另做独立实验或更换配置时，用 --output 指定另一个输出根目录，避免覆盖或混入现有结果。

查看参数：
.venv/bin/python -m eval.experiments --help

检查 small 计划：
.venv/bin/python -m eval.experiments --config config.json

以下为真实执行命令示例，实际已完成次数和状态以 results/ 中的记录为准：
.venv/bin/python -m eval.experiments --execute --config config.json --groups A B
.venv/bin/python -m eval.experiments --execute --config config.json --groups C

以上命令省略 --trial 时各运行 3 次；如需分次运行，分别加 --trial 1、2 或 3。C/01 只读取 B/01 的手册，其余重复同理，B、C 必须使用同一输出根目录；已有组和重复结果不会被覆盖。
正式执行前核对计划中的数据规模、组名、trial、模型、端点、Key 变量名和输出位置。使用新结果目录，避免混用先前实验编号、服务商或模型配置对应的结果。


结果文件（下列路径均相对于输出根目录）

输出根目录只保存以下 2 个公共文件和 A/B/C 目录：
plan.json：仅保留 config 配置快照和 ids；ids 按 train、val、test 保存样本 ID。运行组由 --groups 决定；所需密钥在运行时按所选组检查，方法说明保留在本文档。
summary.csv：各组准确率均值、样本方差、调用用量与耗时汇总；各次完整结果仍在对应 result.json。

各组的 01/02/03 目录均保存以下 3 个文件：
llm_calls.jsonl：按行追加所有阶段的 DeepSeek 请求，完整保留角色、提示词、回答、Token、耗时和错误；使用 stage 与 call_id 定位单次调用。另以 processing_error 事件记录解析和 Curator 应用错误，这类事件不计作额外 API 请求。
predictions.jsonl：逐题保存最终测试的样本 ID、预测、标准答案、正误与错误信息，直接放在各组重复目录下；不再复制原始回答、final_answer 或重复成功标记，原始回答通过 stage/call_id 关联 llm_calls.jsonl。
result.json：本组本次的运行状态、test 中的测试指标、predictions_path 绝对路径、各阶段调用与 Token 汇总、耗时及 errors 中的 API、解析和 Curator 应用错误；不再嵌入完整逐题预测。B 的 training_config 保留训练入口实际参数和 effective_parameters，training 保留训练摘要。C 还保存 selection_k=10、selection_method=fixed_top_k、b_checkpoint 中的 B 组编号与手册路径，以及共享 B 训练和验证用量；这些信息在测试开始前落盘。

B 再保存以下 2 个训练文件：
training/train_results.json：合并逐题更新手册前后的答案和正误、实际反思轮数，各次验证的逐题预测、指标与手册大小，以及 best_checkpoint；small 正常完成时有 5 次验证。每个训练步骤后更新，失败时保留已完成记录和状态。
training/best_playbook.txt：验证准确率提升时立即保存的最佳手册；C 直接读取正常完成的同编号 B 的文件。

C 额外保存 jev_audit.jsonl，记录 Score 请求及 0–3 分档、每个候选经验的原始 score、confidence 和 probabilities、排序依据、选中条目、Token、耗时和错误，便于追溯 top-10 选择；confidence 不参与排序。
三次重复的三组全部正常完成后，共有 38 个输出文件：2 个公共文件、27 个各组共有文件、6 个 B 训练文件和 3 个 C 审计文件。不生成版本化计划、版本化汇总或 invocations 文件。

不再生成独立 data_manifest.json、summary.json、test_metrics.json、evaluation_playbook.txt 或 frozen_selection.json，也不再生成独立请求 JSON、detailed_llm_logs、run_config.json、final_results.json、val_results.json、pre_train_post_train_results.json、bullet_usage_log.jsonl、curator_operations_diff.jsonl、final_playbook.txt 和 intermediate_playbooks 快照；需保留的配置、逐题训练与验证信息、错误和最佳手册已先并入上述文件。常规运行保留完整原始调用；已整理的 A/02、A/03 使用下述最终结果视图。
日志逐条追加、训练记录逐步保存；完整测试预测在该次评测完成后保存。这种持久化不等于自动断点续跑，现有已运行组和重复仍不会被覆盖。
已有结果使用本文所列 A/B/C 定义，不能与不同组定义、反思上限或目录布局的结果直接混用。

计划与运行检查

results/ 根目录只保留 plan.json、summary.csv 和 A/B/C。plan.json 的 config 保存配置快照，ids 保存训练、验证、测试样本 ID；不再保存数据规模统计、重复抽样字段或正式指标标记，也不保留旧计划或来源清单快照。配置位于根目录 config.json，入口和数据位于 eval/。
运行入口核对已有计划的 config 和 ids 是否与当前计划一致，并拒绝覆盖已有组和重复目录。是否调用 API 仅由显式 --execute 决定；默认或 --dry-run 均不调用 API。C 只读取同编号且状态为 complete 的 B 最佳手册，保留 B 的组名、重复编号、手册路径及共享学习用量；模型设置、Score 分数类型与范围、排序规则等检查继续生效。
A/02、A/03 使用 artifact_view=final_predictions：各保留 200 条最终预测及对应回答，清除失败调用和恢复详情，不另行归档。A/02 保持 4096 Token 上限，无答案题仍计错。result.json.test 与 final_llm_usage 对应最终预测和回答；llm 与 llm_usage_including_shared_learning 保留实际累计请求数和已报告 Token，wall_seconds 保留实际累计执行时间。
离线检查已有计划：.venv/bin/python -m eval.experiments --dry-run --config config.json --output results。它核对当前配置与样本 ID，不调用 API，已有计划不改写。以后运行入口仍使用统一文件名，已有组和重复目录不会覆盖。

评测与结果解释

B 固定验证集选出的手册，C 复用 B 的同一份最佳手册并预先固定 k=10；测试标签仅用于程序评分，不传给模型或 Jev。
三组统一使用数值 Exact Match，不额外放宽数值容差。分母固定为全部测试题，API 或解析失败均计错，不跳过样本提高准确率；最终视图只保留当前预测状态。
正式配置汇总 3 次准确率的均值、样本方差，记录 API 完成率、各阶段调用数、输入/输出 Token、耗时、实际反思轮数和手册大小。
百炼与 Jev 用量分开记录；Token、API 调用次数和延迟不是费用，需要明确计费规则或账单证据才能换算。
C 同时报告自身增量用量和加上共享 B 学习过程的总用量；共享部分包含 B 训练和验证，不含 B 的测试调用。整体费用只将同一份 B 学习投入计一次，避免因复用或重复归因失真。
